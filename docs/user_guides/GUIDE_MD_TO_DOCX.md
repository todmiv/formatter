# Инструкция: Конвертация Markdown в DOCX с применением шаблона

## 1. Назначение

Конвертер `md_to_docx.py` преобразует Markdown-файлы в документы DOCX, оформленные по НТД 01-2013 (Редакция 4) — рабочей инструкции организации. При указании DOCX-шаблона стили копируются из него, обеспечивая точное соответствие эталонному оформлению.

## 2. Запуск

### 2.1. Из командной строки (прямой вызов)

```bash
python md_to_docx.py <вход.md> <выход.docx>
```

Примеры:
```bash
# С настройками по умолчанию
python md_to_docx.py "Глава1.md" "Глава1.docx"

# С указанием конфигурации (по умолчанию configs/active/config.yaml)
python md_to_docx.py "Глава1.md" "Глава1.docx"
```

### 2.2. Через CLI (рекомендуемый способ)

```bash
# Конвертация MD → DOCX без шаблона (только конфиг)
python -m src.core.cli format -i document.md -o document.docx -c configs/active/config.yaml

# Конвертация MD → DOCX с применением шаблона
python -m src.core.cli format -i document.md -o document.docx -t "НТД 01-2013 Текстовая часть_4ред.docx"
```

### 2.3. Через GUI

1. Запустите приложение: `python gui_formatter.py`
2. Нажмите кнопку **«Импорт из Markdown»**.
3. Выберите исходный Markdown-файл (`.md` или `.txt`).
4. Укажите путь для сохранения результирующего DOCX-файла.
5. Результат автоматически загрузится в интерфейс для дальнейшего аудита.

### 2.4. Программно (Python)

```python
from md_to_docx import RI2013Converter

# Без шаблона — стили из YAML-конфигурации
converter = RI2013Converter(config_path='configs/active/config.yaml')
converter.convert('input.md', 'output.docx')

# С шаблоном — стили копируются из DOCX-шаблона
converter = RI2013Converter(
    config_path='configs/active/config.yaml',
    template_path='НТД 01-2013 Текстовая часть_4ред.docx'
)
converter.convert('input.md', 'output.docx')
```

## 3. Работа с шаблоном

### 3.1. Что делает шаблон

При указании DOCX-шаблона конвертер:
1. Загружает шаблон как `Document()`.
2. Перебирает все абзацные стили шаблона.
3. Для каждого стиля копирует в выходной документ:
   - **Шрифт**: имя, размер, начертание (жирный, курсив).
   - **Абзац**: выравнивание, отступ первой строки, отступ слева, интервалы (перед/после/межстрочный), разрыв страницы перед абзацем.
4. Стиль сохраняет своё имя из шаблона — это обеспечивает автоматическое сопоставление при конвертации.

### 3.2. Маппинг заголовков

Конвертер автоматически сопоставляет уровни Markdown-заголовков со стилями из конфига через секцию `content_type_styles`:

| Уровень Markdown | Тип контента | Стиль из конфига (пример) |
|---|---|---|
| `# РАЗДЕЛ` / `РАЗДЕЛ X` | `heading_1` | `01_Раздел` |
| `## ГЛАВА` / `ГЛАВА X` | `heading_2` | `02_Глава` |
| `### X.Y Заголовок` | `heading_3` | `03_Пункт` |
| `#### Подпункт` | `heading_4` | `031_Подпункт` |

Если стиль не найден в конфиге, используется стандартный `Heading N`.

### 3.3. Использование шаблона НТД 01-2013

В проекте имеется готовый шаблон: `НТД 01-2013 Текстовая часть_4ред.docx`

```bash
python md_to_docx.py "input.md" "output.docx"
```

Затем в коде:
```python
converter = RI2013Converter(
    config_path='configs/active/config.yaml',
    template_path='НТД 01-2013 Текстовая часть_4ред.docx'
)
converter.convert('input.md', 'output.docx')
```

### 3.4. Извлечение конфигурации из шаблона

Если нужно получить YAML-конфиг из существующего DOCX-шаблона:

```bash
# Через CLI
python -m src.core.cli extract -t template.docx -o config.yaml

# Программно
from src.core.template_extractor import TemplateExtractor

extractor = TemplateExtractor("template.docx")
config = extractor.extract()
extractor.save_yaml("config.yaml", config)
```

## 4. Формат входного Markdown-файла

### 4.1. Заголовки

```markdown
# РАЗДЕЛ 1. НАЗВАНИЕ РАЗДЕЛА
## ГЛАВА 1.1. НАЗВАНИЕ ГЛАВЫ
### 1.1.1. НАЗВАНИЕ ПУНКТА
#### а) наименование подпункта
```

Конвертер также понимает заголовки без markdown-разметки:
```markdown
РАЗДЕЛ 1. ОБЩИЕ ПОЛОЖЕНИЯ
ГЛАВА 1.1. ЦЕЛИ И ЗАДАЧИ
3.1 Анализ территории
```

### 4.2. Обычный текст

```markdown
Обычный текст документа с форматированием. Здесь может быть
**жирный текст** для выделения ключевых терминов.
```

### 4.3. Таблицы

```markdown
Таблица 2.1 — Перечень основных показателей

| Наименование | Значение | Ед. изм. |
|---|---|---|
| Население | 150 000 | чел. |
| Площадь | 120 | км² |
| Плотность | 1 250 | чел./км²
```

### 4.4. Списки

```markdown
- Первый элемент списка
- Второй элемент списка
  - Вложенный элемент

1. Пункт нумерованного списка
2. Второй пункт
```

### 4.5. Примечания

```markdown
Примечание — Текст примечания к таблице.
```

## 5. Конфигурация

### 5.1. Стандартная конфигурация

Конвертер использует YAML-конфигурацию из `configs/active/config.yaml`. Основные параметры:

```yaml
styles:
  Normal:
    font:
      name: "Times New Roman"
      size: 12
    paragraph:
      first_line_indent_cm: 1.25
      line_spacing: 1.15
      alignment: "justify"

  Heading 1:
    font:
      name: "Times New Roman"
      size: 14
    paragraph:
      first_line_indent_cm: 0
      line_spacing: 1.25
      alignment: "left"
      page_break_before: true

# Маппинг типов контента → имена стилей
content_type_styles:
  heading_1: 01_Раздел
  heading_2: 02_Глава
  heading_3: 03_Пункт
  heading_4: 031_Подпункт
  paragraph: 04_Основной текст
  caption: 05_Номер таблицы
  table_name: 051_Название таблицы
  table_note: 055_Примечание после таблицы/рисунка
  table_grid: Table Grid
  list: 06_Перечисление 1 уровень

page_setup:
  portrait:
    left_margin_cm: 2.5
    right_margin_cm: 1.0
    top_margin_cm: 2.0
    bottom_margin_cm: 2.0
  paper_size: "A4"

formatting_rules:
  tables:
    spacing_after_table_pt: 6
```

### 5.2. Секция `content_type_styles`

Секция `content_type_styles` определяет, какие стили конфига используются для каждого типа контента:

| Тип контента | Назначение | Пример из конфига |
|---|---|---|
| `heading_1` | Заголовок уровня 1 (РАЗДЕЛ) | `01_Раздел` |
| `heading_2` | Заголовок уровня 2 (ГЛАВА) | `02_Глава` |
| `heading_3` | Заголовок уровня 3 (ПУНКТ) | `03_Пункт` |
| `heading_4` | Заголовок уровня 4 (ПОДПУНКТ) | `031_Подпункт` |
| `paragraph` | Обычный текст | `04_Основной текст` |
| `caption` | Подпись таблицы/рисунка | `05_Номер таблицы` |
| `table_name` | Название таблицы | `051_Название таблицы` |
| `table_note` | Примечание после таблицы | `055_Примечание...` |
| `table_grid` | Стиль таблицы | `Table Grid` |
| `list` | Элемент списка | `06_Перечисление 1 уровень` |

Если секция отсутствует, используются стандартные имена Word (`Heading 1`, `Normal`, `Caption` и т.д.).

### 5.2. Приоритет стилей

При использовании шаблона стили из шаблона переопределяют стили из конфигурации:
1. Сначала применяются стили из YAML-конфига (через `StyleManager`).
2. Затем поверх них записываются стили из DOCX-шаблона (метод `_copy_styles_from_template`).

## 6. Структура выходного документа

Выходной DOCX-файл содержит:

- **Страница**: А4, поля из конфига (`page_setup`).
- **Шрифт основного текста**: из конфига стиля `paragraph` (например, Times New Roman, 12 пт, межстрочный интервал 1,15).
- **Заголовки**: стили из `content_type_styles` (например, `01_Раздел`, `02_Глава`).
- **Таблицы**: стиль `table_grid` из конфига, шапка с нижней границей, повтор на следующих страницах.
- **Подписи таблиц**: стиль `caption` из конфига (например, `05_Номер таблицы`).
- **Примечания**: стиль `table_note` из конфига (например, `055_Примечание после таблицы/рисунка`).
- **Колонтитулы**: номер страницы (верхний правый), номер раздела/главы (нижний центр).

## 7. Устранение проблем

### Конвертер не находит стили шаблона

Убедитесь, что DOCX-шаблон содержит абзацные стили с нужными именами. Проверить список стилей:

```python
from docx import Document
doc = Document('template.docx')
for style in doc.styles:
    if style.type and style.type.name == 'PARAGRAPH':
        print(style.name)
```

### Неверное форматирование заголовков

Проверьте, что заголовки в Markdown соответствуют паттернам:
- `РАЗДЕЛ X` или `# РАЗДЕЛ X`
- `ГЛАВА X` или `## ГЛАВА X`
- `X.Y Название` или `### X.Y Название`

### Шрифт не применяется

Убедитесь, что шрифт установлен в системе. Конвертер устанавливает `w:eastAsia` атрибут для кириллических шрифтов ( Times New Roman ).

## 8. Пакетная обработка

Для конвертации нескольких файлов:

```bash
# Пакетная конвертация
python -m src.core.cli batch -id input_dir/ -od output_dir/ -t template.docx
```
