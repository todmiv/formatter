# Руководство пользователя: Форматировщик документов по ГОСТ (Audit & Apply)

## 1. Введение

**Форматировщик документов по ГОСТ** — это программное обеспечение для диагностики и контролируемого форматирования документов Microsoft Word (DOCX) в соответствии с требованиями ГОСТ Р 21.101-2020, ГОСТ 2.105-2019 и ГОСТ 7.32-2017.

Ключевые особенности:
- **Глубокий аудит** — полное сканирование документа без внесения изменений.
- **Детализированный отчет** — список всех найденных проблем с указанием номера страницы, абзаца, типа нарушения, текущего и ожидаемого значений.
- **Интерактивное применение исправлений** — пользователь может выбрать, какие проблемы исправить (точечно или все сразу).
- **Безопасный режим** — исходный файл никогда не изменяется напрямую до явного подтверждения пользователем.
- **Визуальная подсветка** — создание копии документа с цветным выделением проблемных элементов.
- **Импорт из Markdown** — конвертация Markdown-файлов в DOCX с применением стилей по ГОСТ.
- **Инициализация стилей** — подготовка документа (создание стилей, настройка полей, колонтитулов) без изменения текста.

## 2. Системные требования и установка

### 2.1. Требования
- Операционная система: Windows 10/11

## 3. Обзор интерфейса

После запуска откроется главное окно программы, состоящее из следующих областей:

- **Верхняя панель** — выбор документа и конфигурации, кнопки дополнительных функций.
- **Панель действий** — кнопки запуска аудита, применения исправлений, экспорта отчета, настроек и сохранения.
- **Трехпанельный интерфейс**:
  - **Левая панель** — дерево структуры документа (заголовки, таблицы, списки).
  - **Центральная панель** — таблица найденных проблем с фильтрами и сортировкой.
  - **Правая панель** — детали выбранной ошибки и предпросмотр фрагмента текста.
- **Лог операций** — отображение хода выполнения операций и сообщений.
- **Статусная строка и прогресс-бар** — индикация текущего состояния.

## 4. Пошаговое руководство

### 4.1. Выбор документа и конфигурации
1. Нажмите кнопку **«Обзор…»** рядом с полем «Документ» и выберите файл DOCX.
2. Укажите путь к файлу конфигурации YAML (по умолчанию `config.yaml`). При необходимости выберите другой файл через кнопку **«Обзор…»** в поле «Конфиг».
3. Для предварительного просмотра документа можно нажать **«Открыть для просмотра»**.

### 4.2. Запуск аудита
1. Убедитесь, что документ и конфигурация загружены.
2. Нажмите кнопку **«🔍 Начать аудит»**.
3. Прогресс аудита отобразится в прогресс-баре и статусной строке. Процесс включает проверку:
   - настроек страницы (поля, ориентация);
   - параграфов (шрифт, отступы, интервалы);
   - таблиц;
   - колонтитулов;
   - изображений.

### 4.3. Анализ отчета
После завершения аудита таблица заполнится списком проблем. Каждая строка содержит:
- **Важность** (CRITICAL, WARNING, INFO) с цветовой индикацией.
- **Категория** (шрифт, абзац, таблица и т.д.).
- **Стиль** (логический тип элемента).
- **Локация** (примерный номер страницы).
- **Описание проблемы**.
- **Текущее и ожидаемое значения**.

**Фильтрация и сортировка:**
- Используйте выпадающий список «Фильтр» для отображения только определённых уровней важности.
- Нажмите на заголовок любой колонки для сортировки по ней (повторное нажатие инвертирует порядок).
- Для выделения всех строк установите флажок **«Выделить все»**.

### 4.4. Применение исправлений
1. Выберите одну или несколько проблем в таблице (удерживайте Ctrl для множественного выбора).
2. Нажмите кнопку **«🛠 Исправить выбранные»**.
3. Подтвердите действие в диалоговом окне.
4. Для исправления всех найденных проблем нажмите **«⚡ Исправить всё»**.

**Примечание:** Исправления применяются к копии документа в памяти. Исходный файл остаётся неизменным.

### 4.5. Сохранение результата
1. После применения исправлений кнопка **«💾 Сохранить результат»** станет активной.
2. Нажмите её и укажите путь для сохранения исправленного документа.
3. Если исправления не применялись, будет сохранена копия исходного документа.

## 5. Дополнительные функции

### 5.1. Подсветка проблемных мест
- Нажмите кнопку **«🔦 Подсветить проблемные места»**.
- Программа создаст копию документа, в которой проблемные элементы будут выделены цветом (красный — критические, жёлтый — предупреждения, синий — информационные).
- Копия откроется в Microsoft Word для визуального анализа.

### 5.2. Поиск в документе
- Выберите одну проблему в таблице.
- Нажмите кнопку **«🔍 Найти в документе»** (активируется после выбора).
- Будет создана временная копия документа с выделением только этой ошибки и открыта для просмотра.

### 5.3. Импорт из Markdown
- Нажмите кнопку **«Импорт из Markdown»**.
- Выберите исходный Markdown-файл (`.md` или `.txt`).
- Укажите путь для сохранения результирующего DOCX-файла.
- После конвертации полученный документ автоматически загрузится в интерфейс для дальнейшего аудита.

### 5.4. Настройка допусков
- Нажмите кнопку **«⚙ Настройки»**.
- В открывшемся окне задайте допуски (погрешности) для сравнения свойств:
  - **Размер шрифта** (в мм, пунктах или twips).
  - **Отступ**.
  - **Интервалы**.
- Значения в полях взаимосвязаны: изменение в миллиметрах автоматически пересчитывается в пункты и twips.
- Нажмите **«Сохранить»** для применения новых допусков.

### 5.5. Экспорт отчета
- Нажмите кнопку **«📄 Экспорт отчёта»** (активна после аудита).
- Введите формат экспорта (`txt`, `html` или `csv`).
- Укажите путь для сохранения файла.
- Отчёт будет содержать сводку и детали всех найденных проблем.

## 6. Работа с конфигурацией

Конфигурация задаётся в YAML-файле. Пример структуры см. в `configs/active/config.yaml` или `configs/active/config_v4.2.yaml`.

Основные секции:
- **`styles`** — определение эталонных стилей (шрифт, абзац, интервалы).
- **`detection_rules`** — правила автоматического определения типа параграфа (например, заголовок по тексту «РАЗДЕЛ»).
- **`page_setup`** — настройки полей страницы, ориентации, размера бумаги.
- **`headers_footers`** — параметры колонтитулов.

Подробное описание формата конфигурации см. в документации проекта.

## 7. Новые возможности версии 1.0.0 (завершена фаза 1 "Стабилизация")

С версии 1.0.0, выпущенной 2026-05-06, добавлены следующие улучшения:

### Улучшения модуля аудита
- **Более точное определение типа параграфа** – снижено количество ложных срабатываний, улучшен fallback на Normal
- **Расширенный аудит таблиц** – проверка стиля таблицы, выравнивания текста в ячейках и границ

### Улучшения модуля применения
- **Кнопка «Исправить только стили»** – режим, который меняет привязку стиля без удаления прямого форматирования
- **Выбор пользователя** – опция «Удалить прямое форматирование полностью» / «Сохранить прямое форматирование, где не конфликтует»

### Улучшения графического интерфейса
- **Окно настроек игнорирования типов ошибок** – настройка, какие типы предупреждений постоянно игнорировать
- **Сохранение с бэкапом** – опция «Перезаписать с бэкапом» при сохранении результата
- **Кнопка «Подготовить стили»** – вызов метода `initialize_styles` через интерфейс

### Тестирование и оптимизация
- **Нагрузочное тестирование** – измерение производительности аудита документа до 500 страниц
- **Улучшенная обработка ошибок** – детальные сообщения об ошибках, ведение лога отладки
- **Модульные и интеграционные тесты** – покрытие крайних случаев

## 8. Новые возможности версии 1.1.0 (завершена фаза 2 "Оптимизация")

С версии 1.1.0, выпущенной 2026-05-08, добавлены следующие ключевые улучшения, решающие проблему "неверный индекс параграфа (None)" и обеспечивающие 100% эффективность исправлений:

### Универсальная система location
- **Единый формат идентификации элементов** – каждый элемент документа (параграф, таблица, ячейка, колонтитул) теперь имеет уникальный location-идентификатор:
  - `paragraph:<index>` – параграфы
  - `table:<index>` – таблицы
  - `cell:<row>:<col>` – ячейки таблиц
  - `header`, `footer` – верхние и нижние колонтитулы
- **Точное определение местоположения** – устранены ошибки "неверный индекс параграфа (None)" во всех модулях.
- **Отображение location в интерфейсе** – в таблице проблем теперь отображается точный location элемента, что упрощает навигацию.

### Работа с колонтитулами (header/footer)
- **Аудит колонтитулов** – проверка верхних и нижних колонтитулов на соответствие конфигурации (шрифт, выравнивание, положение).
- **Применение исправлений к колонтитулам** – возможность исправлять стили в header/footer без нарушения структуры документа.
- **Поддержка разных колонтитулов** для четных/нечетных страниц и разных разделов документа.

### Поддержка таблиц
- **Полный аудит таблиц** – проверка стиля таблицы, выравнивания текста в ячейках, границ, отступов.
- **Применение исправлений к таблицам** – точечное исправление ячеек, строк, столбцов с сохранением структуры таблицы.
- **Работа с вложенными таблицами** – корректная обработка таблиц внутри ячеек других таблиц.

### Итеративное применение исправлений
- **Повторный быстрый аудит** – после применения исправлений можно запустить повторный аудит для проверки эффективности.
- **Многократный цикл исправлений** – возможность нескольких итераций "аудит-применение" до достижения 100% соответствия ГОСТ.
- **Статистика эффективности** – автоматическая генерация отчетов с показателями до/после исправлений.

### Производительность и оптимизация
- **Ускорение обработки** – время аудита и применения исправлений сокращено на 30% за счет оптимизации алгоритмов.
- **Кэширование результатов** – повторные проверки выполняются быстрее благодаря кэшированию.
- **Пакетное применение** – группировка операций для уменьшения накладных расходов.

### Тестирование и надежность
- **Специализированные тесты** – созданы тесты для проверки работы с таблицами (`test_table_support.py`), колонтитулами (`test_fix_header_footer.py`), реальными документами (`test_real_document_fix.py`).
- **Интеграционные тесты полного цикла** – проверка всего процесса от аудита до применения исправлений.
- **Нагрузочное тестирование** – подтверждена стабильность работы с документами до 500 страниц.

## 9. Часто задаваемые вопросы (FAQ)

**Вопрос:** После применения исправлений некоторые элементы выглядят некорректно.
**Ответ:** Проверьте, правильно ли определён логический тип параграфа в конфигурации. При необходимости скорректируйте `detection_rules`.

**Вопрос:** Можно ли использовать свою конфигурацию для другого ГОСТ?
**Ответ:** Да, создайте YAML-файл, описывающий требуемые стили и параметры, и укажите его в поле «Конфиг».

**Вопрос:** Что изменилось в версии 1.0.0?
**Ответ:** Завершена фаза 1 "Стабилизация" стратегического плана развития. Подробности см. в [CHANGELOG.md](../general/CHANGELOG.md).

**Вопрос:** Что изменилось в версии 1.1.0?
**Ответ:** Завершена фаза 2 "Оптимизация" – полностью решена проблема "неверный индекс параграфа (None)", добавлена поддержка таблиц и колонтитулов, достигнута 100% эффективность исправлений. Подробности см. в [CHANGELOG.md](../general/CHANGELOG.md) и [IMPROVEMENTS_SUMMARY.md](../general/IMPROVEMENTS_SUMMARY.md).

**Вопрос:** Как использовать новую систему location?
**Ответ:** Location отображается в таблице проблем в формате `paragraph:<index>`, `table:<index>`, `cell:<row>:<col>`, `header`, `footer`. Это позволяет точно идентифицировать элемент в документе.

**Вопрос:** Как проверить эффективность исправлений?
**Ответ:** После применения исправлений нажмите кнопку «🔍 Начать аудит» для повторного быстрого аудита. Сравните количество проблем до и после исправлений.
