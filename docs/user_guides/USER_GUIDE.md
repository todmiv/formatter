# Руководство пользователя: Форматировщик документов по ГОСТ (v2.0)

## 1. Введение

**Форматировщик документов по ГОСТ** — это программное обеспечение для форматирования документов Microsoft Word (DOCX) в соответствии с требованиями ГОСТ Р 21.101-2020, ГОСТ 2.105-2019 и ГОСТ 7.32-2017.

### Ключевой принцип (v2.0)
Документы **создаются заново из шаблона**, а не "исправляются". Это гарантирует сохранение форматирования.

### Возможности
- **Конвертация MD→DOCX** — пошаговый мастер для создания документов из Markdown
- **Аудит (read-only)** — анализ документа без внесения изменений
- **Применение шаблона** — создание нового документа с стилями из шаблона
- **Извлечение стилей** — экспорт стилей из шаблона в YAML/JSON
- **Редактор конфигураций** — визуальное редактирование настроек

## 2. Системные требования и установка

### 2.1. Требования
- Операционная система: Windows 10/11

## 3. Обзор интерфейса

После запуска откроется главное окно с 4 вкладками:

### Вкладка "MD → DOCX" (пошаговый мастер)
- Выбор Markdown файла
- Выбор конфига и шаблона
- Кнопки: Конвертировать, Аудит, Сохранить
- Лог и прогресс-бар

### Вкладка "Аудит"
- Выбор DOCX файла и конфига
- Трехпанельный интерфейс:
  - **Левая** — дерево структуры документа
  - **Центральная** — таблица расхождений
  - **Правая** — детали и предпросмотр
- Кнопки: Аудит, Подсветить, Отчёт, Настройки

### Вкладка "Шаблоны"
- **Шаг 1 (необязательный)** — Извлечь YAML-конфиг из DOCX-шаблона (для использования на вкладке «Аудит»)
- **Шаг 2** — Применить шаблон к документу: переносит текст вашего DOCX в шаблон, сохраняя стили и оформление. Оригинал НЕ изменяется — результат сохраняется в новый файл
- Просмотр доступных стилей шаблона
- Редактор YAML-конфигов

### Вкладка "Замена стилей" (новая)
- Полная замена styles.xml из DOCX-источника в целевой документ
- Выбор источника с предпросмотром списка стилей
- Варианты: создать новый файл или перезаписать целевой
- Прогресс-бар и лог

### Вкладка "Настройки"
- Допуски (шрифт, отступы, интервалы)
- Игнорирование ошибок

## 4. Пошаговое руководство

### 4.1. Конвертация Markdown → DOCX (главный сценарий)
1. Перейдите на вкладку **«MD → DOCX»**.
2. Выберите Markdown файл через **«Обзор...»**.
3. Укажите конфиг (по умолчанию `config.yaml`).
4. Нажмите **«🔄 Конвертировать»**.
5. Дождитесь завершения — документ создан со стилями из шаблона.

### 4.2. Форматирование DOCX по шаблону
1. Перейдите на вкладку **«Шаблоны»**.
2. **Шаг 2 — «Применить шаблон к документу»**:
   - **«Ваш документ (текст)»** — выберите ваш DOCX-файл
   - **«DOCX-шаблон (оформление)»** — выберите шаблон (например, `ОБРАЗЕЦ_Миасский.docx`)
3. Нажмите **«Применить шаблон → сохранить результат»**.
4. В диалоге «Сохранить как» укажите путь для **НОВОГО** документа.
5. Исходный файл остаётся неизменным.

### 4.3. Анализ документа (read-only)
1. Перейдите на вкладку **«Аудит»**.
2. Выберите DOCX файл и конфиг.
3. Нажмите **«🔍 Аудит»**.
4. Просмотрите таблицу расхождений.
5. Для исправления: выберите строки и нажмите **«Исправить выбранное»** или **«Исправить всё»**.
6. Результат сохраняется в новый файл `_fixed.docx`.
7. При необходимости экспортируйте отчёт через **«📄 Отчёт»**.

### 4.4. Извлечение конфига из шаблона (необязательно)
1. Перейдите на вкладку **«Шаблоны»**.
2. **Шаг 1 — «Извлечь конфиг из DOCX-шаблона»** (необязательный):
   - **«DOCX-шаблон (источник стилей)»** — выберите шаблон
   - **«Сохранить YAML-конфиг как»** — укажите путь для конфига
3. Нажмите **«Извлечь и сохранить конфиг»**.
4. Полученный YAML-файл можно использовать на вкладке **«Аудит»**.

## 5. Дополнительные функции

### 5.1. Подсветка проблемных мест
- На вкладке "Аудит" нажмите **«🔦 Подсветить»**.
- Программа создаст копию документа с выделением расхождений.
- Копия откроется в Word для визуального анализа.

### 5.2. Экспорт отчёта
- На вкладке "Аудит" нажмите **«📄 Отчёт»**.
- Выберите формат: TXT, HTML или CSV.
- Отчёт содержит сводку и детали всех расхождений.

### 5.3. Настройка допусков
- На вкладке "Аудит" нажмите **«⚙»**.
- Задайте допуски для сравнения: размер шрифта, отступы, интервалы.

### 5.4. Создание пустого документа из шаблона
- На вкладке "Шаблоны" выберите шаблон.
- Нажмите **«📄 Создать пустой документ»**.
- Получится DOCX с настройками шаблона (поля, колонтитулы, стили) без содержимого.

## 6. Работа с конфигурацией

Конфигурация задаётся в YAML-файле. Пример структуры см. в `configs/active/config.yaml` или `configs/active/config_v4.2.yaml`.

Готовые конфигурации в `configs/active/`:
- **`config.yaml`** — базовый конфиг по НТД 01-2013 (аудит по умолчанию в GUI/CLI).
- **`config_НТД_2026.yaml`** — универсальный конфиг по НТД 01-2013 (редакция август 2026): интервал 1,0, поля 20/10/20/20 мм, заголовки 12 пт, подписи таблиц/рисунков по центру со сквозной нумерацией, нижний колонтитул пуст.
- **`config_Эталон.yaml`** — конфиг записок по образцу «Эталон.docx»: те же параметры, что в `config_НТД_2026.yaml`, но имена стилей соответствуют эталону (`041_Основной текст`, `06_Перечисление тире`, `05_Номер и название таблицы/рисунка` и т.д.), поэтому аудит образца не даёт ложных срабатываний по именам стилей.
- **`config_v4.2.yaml`** — вариант конфига для проектов.
- `config_from_*.yaml` — конфиги, извлечённые из DOCX-шаблонов (TemplateExtractor).

Основные секции:
- **`styles`** — определение эталонных стилей (шрифт, абзац, интервалы).
- **`detection_rules`** — правила автоматического определения типа параграфа (например, заголовок по тексту «РАЗДЕЛ»).
- **`page_setup`** — настройки полей страницы, ориентации, размера бумаги.
- **`headers_footers`** — параметры колонтитулов.

Подробное описание формата конфигурации см. в документации проекта.

## 8. Новые возможности версии 1.1.0 (завершена фаза 2 "Оптимизация")

С версии 1.1.0, выпущенной 2026-05-08, добавлены следующие ключевые улучшения, решающие проблему "неверный индекс параграфа (None)" и обеспечивающие 100% эффективность исправлений:

### Универсальная система location
- **Единый формат идентификации элементов** – каждый элемент документа (параграф, таблица, ячейка, колонтитул) теперь имеет уникальный location-идентификатор:
  - `paragraph:<index>` – параграфы
  - `table:<index>` – таблицы
  - `cell:<row>:<col>` – ячейки таблиц
  - `header`, `footer` – верхние и нижние колонтитулы
- **Точное определение местоположения** – устранены ошибки "неверный индекс параграфа (None)" во всех модулях.
- **Отображение location в интерфейсе** – в таблице проблем теперь отображается точный location элемента, что упрощает навигацию.

### Работа с колонтитулами (header/footer)
- **Аудит колонтитулов** – проверка верхних и нижних колонтитулов на соответствие конфигурации (шрифт, выравнивание, положение).
- **Применение исправлений к колонтитулам** – возможность исправлять стили в header/footer без нарушения структуры документа.
- **Поддержка разных колонтитулов** для четных/нечетных страниц и разных разделов документа.

### Поддержка таблиц
- **Полный аудит таблиц** – проверка стиля таблицы, выравнивания текста в ячейках, границ, отступов.
- **Применение исправлений к таблицам** – точечное исправление ячеек, строк, столбцов с сохранением структуры таблицы.
- **Работа с вложенными таблицами** – корректная обработка таблиц внутри ячеек других таблиц.

### Итеративное применение исправлений
- **Повторный быстрый аудит** – после применения исправлений можно запустить повторный аудит для проверки эффективности.
- **Многократный цикл исправлений** – возможность нескольких итераций "аудит-применение" до достижения 100% соответствия ГОСТ.
- **Статистика эффективности** – автоматическая генерация отчетов с показателями до/после исправлений.

### Производительность и оптимизация
- **Ускорение обработки** – время аудита и применения исправлений сокращено на 30% за счет оптимизации алгоритмов.
- **Кэширование результатов** – повторные проверки выполняются быстрее благодаря кэшированию.
- **Пакетное применение** – группировка операций для уменьшения накладных расходов.

### Тестирование и надежность
- **Специализированные тесты** – созданы тесты для проверки работы с таблицами (`test_table_support.py`), колонтитулами (`test_fix_header_footer.py`), реальными документами (`test_real_document_fix.py`).
- **Интеграционные тесты полного цикла** – проверка всего процесса от аудита до применения исправлений.

## 9. Редактор конфигураций (версия 1.2.0)

### 9.1. Обзор

**Редактор конфигураций** — визуальный инструмент для редактирования YAML-конфигураций ГОСТ без ручного правления текста файла. Открывается из основного окна приложения по кнопке **«Открыть для редактирования»**.

### 9.2. Запуск

1. В главном окне приложения укажите путь к конфигурационному YAML-файлу в поле **«Конфиг»**.
2. Нажмите кнопку **«Открыть для редактирования»** справа от поля «Конфиг».
3. Откроется окно редактора конфигураций.

### 9.3. Интерфейс редактора

Окно редактора (1200×800) состоит из:

- **Дерево конфига (левая панель)** — структура конфигурации в виде дерева:
  - Стили (Normal, Heading 1, Heading 2, и др.)
  - Правила определения
  - Настройки страницы
  - Колонтитулы
  - Правила форматирования
  - Валидация
  - Федеральные/региональные проекты

- **Панель редактирования (правая панель)** — поля для редактирования выбранного элемента:
  - Чекбоксы для булевых значений (Включён, Жирный, Курсив)
  - Выпадающие списки для enum-значений (Выравнивание, Трансформация текста)
  - Поля ввода для числовых значений (Размер шрифта, Отступы, Интервалы)
  - Выбор цвета для цветовых параметров

- **Предпросмотр стиля (нижняя правая панель)** — Canvas с визуализацией:
  - Образец шрифта (имя, размер, начертание, цвет)
  - Индикатор выравнивания (left/center/right/justify)
  - Линейка отступов (красная строка в см)

### 9.4. Редактирование стилей

1. В дереве выберите нужный стиль (например, **Normal** или **Heading 1**).
2. Справа отобразятся группы полей:
   - **Шрифт**: имя, размер, жирный, курсив, цвет
   - **Абзац**: отступ 1-й строки, межстрочный интервал, интервал перед/после, выравнивание
   - **Таблица**: автоподбор, фикс. ширина, высота строки, стиль границ
3. Изменения применяются немедленно к модели и предпросмотру.
4. Включите/отключите стиль флажком **«Включён»**.

### 9.5. Редактирование других секций

- **Правила определения** — редактируются как YAML-текст в окне редактора.
- **Настройки страницы** — поля для полей страницы (левое, правое, верхнее, нижнее) в книжной и альбомной ориентации.
- **Колонтитулы** — настройки верхнего и нижнего колонтитулов (включение, положение, содержимое, выравнивание, шрифт).
- **Правила форматирования** — редактируются как YAML-текст.

### 9.6. Валидация

Нажмите кнопку **«Проверить»** в toolbar редактора для проверки всех значений:
- Размер шрифта: 1–100 пт
- Отступы: 0–10 см
- Интервалы: 0.5–5.0 (множитель) или 0–100 пт
- Цвета: допустимые имена или HEX-коды (#RGB, #RRGGBB)
- Выравнивание: left, center, right, justify

При обнаружении ошибок отобразится список с указанием поля и описанием проблемы.

### 9.7. Сохранение

- **Сохранить** — перезаписать текущий файл конфигурации.
- **Сохранить как...** — сохранить в новый файл.
- При закрытии с несохранёнными изменениями программа предложит сохранить.

После сохранения конфигурация автоматически перезагружается в основном приложении — повторный аудит будет выполняться с обновлёнными настройками.

### 9.8. Советы

- Используйте **«Развернуть/Свернуть»** для навигации по дереву конфига.
- Изменения в предпросмотре обновляются в реальном времени при редактировании полей шрифта и абзаца.
- Для сложных секций (правила форматирования, определения) редактируйте YAML-текст напрямую.

## 10. Часто задаваемые вопросы (FAQ)

**Вопрос:** Почему убраны кнопки "Исправить всё" и "Исправить выбранные"?
**Ответ:** В v2.0 изменён подход: вместо "исправления" документов используется создание новых из шаблона. Это гарантирует сохранение форматирования.

**Вопрос:** Как форматировать существующий DOCX по шаблону?
**Ответ:** Перейдите на вкладку "Шаблоны" → секция "Применение шаблона к документу" → выберите исходный файл и шаблон → нажмите "Применить шаблон". Будет создан НОВЫЙ документ.

**Вопрос:** Можно ли использовать свою конфигурацию?
**Ответ:** Да, создайте YAML-файл и укажите его в поле "Конфиг". Или извлеките конфиг из существующего шаблона через вкладку "Шаблоны".

**Вопрос:** Какой шаблон использовать по умолчанию?
**Ответ:** Для документов по НТД 01-2013 используйте `ОБРАЗЕЦ_Том II. Материалы по обоснованию_Миасский.docx`.

**Вопрос:** Что делать, если аудит показывает много расхождений?
**Ответ:** Расхождения — это информация, а не ошибки. Прямое форматирование в документе может быть осознанным выбором автора. Используйте "Применить шаблон" для создания нового документа с правильными стилями.

**Вопрос:** Как отредактировать конфигурацию?
**Ответ:** Нажмите "Ред." рядом с полем "Конфиг" или используйте вкладку "Шаблоны" → "Открыть редактор".
