# Журнал изменений (Changelog)

Все значительные изменения в проекте "Форматировщик документов по ГОСТ" будут документироваться в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и проект придерживается [Семантического версионирования](https://semver.org/lang/ru/).

## [2.4.0] - 2026-07-22

### Исправлено
- **Многоуровневые шапки таблиц** (таблица 3.3.5 в ОБРАЗЕЦ) — парсер корректно обрабатывает таблицы с подзаголовками в нескольких строках. Столбцы совпадают через vMerge + gridSpan
- **Строки-заголовки групп** (таблица 3.3.4) — строки "Число прибывших", "Женщины", "Мужчины" с пустыми ячейками данных получают gridSpan на всю ширину таблицы
- **Data rows gridSpan** — строки данных получают gridSpan для выравнивания с шапкой таблицы
- **3+ уровень шапок** (таблица 3.3.6) — поддержка 3 строк шапки с vMerge и gridSpan
- **Стиль List Paragraph** — bullet списки теперь используют стиль `Normal` (как в ОБРАЗЕЦ), нумерованные — `List Paragraph`
- **Разделительная строка в Markdown** — парсер ищет разделитель на любой позиции (не только [1]), корректно обрабатывает таблицы с шапкой из нескольких строк

### Добавлено
- Метод `_detect_multi_level_header()` — определение N-уровневых шапок (vMerge + gridSpan)
- Метод `_apply_multi_level_merges()` — применение vMerge и gridSpan для N строк шапки
- Метод `_apply_group_header_spans()` — обработка строк-заголовков групп (gridSpan на всю ширину)
- Метод `_apply_data_row_gridspan()` — применение gridSpan к строкам данных для выравнивания с шапкой
- Метод `_setup_subheader_row()` — настройка строк подзаголовков (bold + centered)

## [2.3.1] - 2026-07-21

### Исправлено
- **Списки: маркированные отображались как нумерованные** — дефолтный numbering part Document() имел numId=2 → bullet вместо decimal. Созданы собственные определения: numId=100 (bullet '•') и numId=101 (decimal '1.')
- **Пустые ячейки в таблицах удалялись** — `_parse_table_data()` фильтровал пустые строки из split('|'). Исправлено: сохраняются внутренние пустые ячейки, нормализуются длины строк
- **Разрывы текста внутри предложений** — конвертер не объединял непрерывные строки в один абзац. Добавлено объединение в `_process_content()` + очистка `\n` в `_clean_text()`
- **Дубликаты номеров таблиц** — `table_counter` инкрементировался безусловно, даже при наличии вручную заданной подписи. Теперь инкремент только при `has_caption=False`
- **Лишние абзацы в колонтитулах** — добавлен метод `_cleanup_headers_footers()` для удаления пустых абзацев из header/footer
- **Парсер таблиц не обрабатывал пустые строки** — таблицы с пустыми строками между шапкой и данными разбивались на две. Теперь парсер объединяет через пустые строки
- **vMerge (объединение ячеек)** — переписан алгоритм группировки: группирует строки по значению первого столбца, применяет restart/continue к группам из 2+ строк

### Добавлено
- Конфиг-параметр `formatting_rules.tables.vertical_merge_first_column` (вкл по умолчанию)
- YAML-конфиг `config_Эталон_V4.4.yaml` исправлен (все не-YAML строки закомментированы)

## [2.3.0] - 2026-07-15

  - Метод `_init_style_map()` — инициализация маппинга из конфига при старте
  - Метод `_ensure_all_config_styles()` — создание всех стилей из `content_type_styles` до начала конвертации
- **Убран хардкод шрифта `'Times New Roman'`** из `_add_rich_text()` — теперь берётся из конфига текущего стиля (`styles[стиль].font.name`, `east_asia`)

- **Убран хардкод выравнивания подписей** — `WD_ALIGN_PARAGRAPH.CENTER` / `RIGHT` заменены на стилевое выравнивание из конфига

### Исправлено
- **Синий цвет в заголовках**: удалён `color: 2E74B5` из `Heading 2` в конфиге — теперь наследуется чёрный цвет
- **Нумерация таблиц смещалась справа налево**: конвертер использовал хардкод `'Caption'` вместо стиля `05_Номер таблицы` из конфига. Аудитор не находил стиль → менял на `Normal` (justify)

- **Центрирование таблиц**: конвертер хардкодил `alignment = CENTER` для подписей, перебивая стиль `05_Номер таблицы` (right) из конфига

## [2.2.2] - 2026-07-14

### Исправлено
- **Аудит колонтитулов не распознавал нумерацию страниц через SDT**: заголовки документа содержат нумерацию страниц через Structured Document Tags (`w:sdt` с `w:docPartObj`), которые оборачивают параграфы на уровне колонтитула. python-docx не отображает их как текст (`paragraph.text` пустой), поэтому аудит считал заголовки отсутствующими. Метод `_hf_has_content()` теперь проверяет XML как параграфа, так и его родителя, а также XML самого колонтитула.
- **Первая страница шаблона с пустыми колонтитулами**: экстрактор конфига определяет, что первая секция имеет пустые колонтитулы, а остальные — нет, и помечает `first_page_empty: true`. Аудит пропускает проверку первой секции при наличии этого флага.
- **Аудит выравнивания проверял только отсутствие прямого форматирования**: ранее проверка выравнивания полностью пропускалась при наличии прямого `w:jc`, даже если значение не соответствовало конфигу. Теперь прямое форматирование тоже проверяется — аудит сравнивает фактическое значение `w:jc` с ожидаемым из конфига.

## [2.2.1] - 2026-07-14

### Исправлено
- **Аудит выравнивания игнорировал наследование от стиля**: `get_paragraph_alignment()` и `AuditEngine._check_paragraph_formatting()` не учитывали выравнивание, наследуемое от стиля параграфа. Если у параграфа не было прямого форматирования `w:jc`, аудит по умолчанию считал выравнивание `left`, хотя реальное значение наследовалось из определения стиля (например, `justify` для Normal, `right` для "05_Номер таблицы"). Это вызывало ложные срабатывания — 257 предупреждений при аудите шаблона, из которого был извлечён тот же конфиг.
- Исправлено добавлением fallback: при отсутствии прямого `w:jc` читается `paragraph.style.paragraph_format.alignment`.
- **Аудит колонтитулов дублировал ошибки для связанных секций**: если секция имела `is_linked_to_previous=True`, аудит всё равно проверяла её колонтитул и报告ляла ошибку "отсутствует", хотя колонтитул наследуется от предыдущей секции. Для документа с 48 секциями это давало 47 ложных срабатываний.
- Исправлено: секции с связанными колонтитулами (`linked_to_previous`) теперь пропускаются при аудите.

## [2.2.0] - 2026-07-09

### Исправлено
- **Критический баг `ensure_style_exists`**: при отсутствии стиля `Normal` в DOCX-документе (например, шаблоны с кастомными стилями `MdParagraph`, `MdSpace`) метод выбрасывал `KeyError` и не создавал целевой стиль. Исправлено: добавлен `_find_existing_base_style()`, который ищет `Normal` → `Обычный` → первый доступный непользовательский стиль → создаёт `Normal` с нуля.
- **`ParagraphApplier`**: при ошибке назначения стиля (`paragraph.style = ...`) метод молча возвращал `True`, и исправление считалось успешным. Теперь возвращает `False` и корректно считает `failed`.
- **PAGE-категория не исправлялась**: `ApplyOrchestrator` не обрабатывал проблемы категории `PAGE` (поля страницы). Добавлен метод `_apply_page_fix()`, применяющий настройки полей из конфига.
- **PAGE-проблемы были неисправимы**: аудит ставил `auto_fixable=False` и пустой `payload` для полей страницы. Исправлено: `auto_fixable=True`, `payload={'prop': 'left_margin'}` и т.д.
- **Таблицы без стиля "Table Grid"**: `TableApplier` пытался назначить стиль, но если он отсутствовал в docx — получал ошибку. Добавлен `_ensure_table_style()`, создающий стиль с сеткой границ при его отсутствии.
- **Кнопки исправления отсутствовали в GUI**: `btn_fix_selected`, `btn_fix_all`, `btn_fix_styles_only` использовались в коде, но не создавались в интерфейсе. Добавлены в панель действий.
- **Правило определения Heading 4**: regex `^[А-Я][а-я]+\\s+` матчил ЛЮБОЕ слово с заглавной русской буквой. Заменено на `^Пункт\\s+\\d+` и `^ПОДПУНКТ\\s`.

### Изменено
- **Вкладка «Шаблоны» — редизайн**: перестроена по шагам с пояснениями:
  - Шаг 1 (необязательный): Извлечь YAML-конфиг из DOCX-шаблона (для вкладки «Аудит»)
  - Шаг 2: Применить шаблон к документу (оригинал не изменяется, результат в новый файл)
  - Удалена избыточная кнопка «Создать пустой документ»
- **Оптимизация сборки PyInstaller**: добавлены excludes для `numpy`, `scipy`, `pandas`, `numba`, `llvmlite`, `sympy`, `tqdm`, `bs4`, `pygments`, `cryptography` и др. Размер exe: 138 МБ → 25 МБ.

## Примечания по версионированию

- **MAJOR** версия увеличивается при внесении несовместимых изменений API
- **MINOR** версия увеличивается при добавлении функциональности обратно совместимым образом  
- **PATCH** версия увеличивается при обратно совместимых исправлениях ошибок
