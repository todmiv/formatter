# Статус проекта Formatter_modification

## Обзор
Проект "Форматировщик документов по ГОСТ" — программное обеспечение для форматирования документов Word (DOCX) по ГОСТ Р 21.101-2020.

**Дата актуализации:** 2026-07-15
**Текущая версия:** 2.3.0
**Статус:** ✅ **Готов к промышленному использованию**

## Ключевые возможности

### Аудит и исправление (основной рабочий процесс)
- **Аудит** — сканирование DOCX и сравнение свойств (шрифт, отступ, интервал, стиль) с эталоном из YAML-конфига
- **Исправление** — автоматическое применение стилей, шрифтов, полей страницы, стилей таблиц и колонтитулов. Результат — новый файл `_fixed.docx`, оригинал не изменяется
- **Поддерживаемые категории исправлений:** FONT, PARAGRAPH, STYLE, TABLE (Table Grid), PAGE (поля страницы), HEADER_FOOTER

### Шаблон-based форматирование
- **Применение шаблона** — перенос текста DOCX-документа в шаблон с сохранением стилей и оформления
- **Извлечение конфига** — генерация YAML-конфига из DOCX-шаблона для использования в аудите

### Другие возможности
- **Конвертация MD→DOCX** — пошаговый мастер
- **Замена стилей** — raw XML замена styles.xml из DOCX-источника
- **Редактор конфигураций** — визуальное редактирование YAML
- **Визуальная подсветка** — выделение проблемных мест в документе
- **Экспорт отчётов** — TXT, HTML, CSV

## Исправления v2.3.0 (2026-07-15)

### Конвертер MD→DOCX — полный переход на конфиг--driven подход
- **Удалён весь хардкод стилей** — конвертер теперь определяет все стили, шрифты, размеры и интервалы из YAML-конфига

- **Динамический резолв стилей** — метод `_resolve_style(content_type)`取代 хардкод `TEMPLATE_STYLE_MAP`
- **Хелперы для таблиц** — `_get_table_cell_format()` и `_apply_cell_format()`取代 повторяющийся код

### Исправления форматирования

- **Примечания** — стиль `055_Примечание после таблицы/рисунка` теперь применяется из конфига вместо хардкода `'Table Note'`

## Исправления v2.2.0 (2026-07-09)

- **Кнопки исправления** — `btn_fix_selected`, `btn_fix_all`, `btn_fix_styles_only` отсутствовали в GUI

### Оптимизация сборки

## Архитектура (v2.2.0)
```
DOCX + YAML-конфиг → AuditEngine → Список проблем
                                       ↓
                                ApplyOrchestrator
                                ├── FontApplier (шрифты)
                                ├── ParagraphApplier (стили, абзацы)
                                ├── TableApplier (стили таблиц)
                                ├── HeaderFooterApplier (колонтитулы)
                                └── _apply_page_fix (поля страницы)
                                       ↓
                                  DOCX_fixed.docx
```

## Использование

### Основной рабочий процесс
1. Откройте DOCX на вкладке «Аудит»
2. Выберите YAML-конфиг (или создайте через «Шаблоны → Шаг 1»)
3. Нажмите «🔍 Аудит»
4. Выберите проблемы → «Исправить выбранное» или «Исправить всё»
5. Результат сохраняется в `_fixed.docx`

### Форматирование по шаблону
1. Вкладка «Шаблоны» → Шаг 2
2. Укажите ваш документ и DOCX-шаблон
3. Нажмите «Применить шаблон → сохранить результат»

- **Результат:** Шапка и тело таблицы имеют идентичные фиксированные ширин колонок.
