## 10. Известные проблемы конвертера MD→DOCX

### Критические
- **[x] Многоуровневые шапки таблиц** (таблица 3.3.5 в ОБРАЗЕЦ) — парсер не обрабатывает таблицы с подзаголовками в нескольких строках. Столбцы не состыковываются. ✅ **Исправлено** — добавлена поддержка vMerge и gridSpan для многоуровневых шапок.

### Средние
- **Маркированные списки в ОБРАЗЕЦ** (раздел 3.3 в ОБРАЗЕЦ) — в оригинале используются списки с дефисами `-` (маркеры), а не нумерованные списки. Текущий конвертер корректно обрабатывает `-` списки через `_add_list_item(list_type='bullet')`.
- **[x] Группировка строк в таблицах** (таблица 3.3.4) — строки-заголовки групп ("Число прибывших", "Женщины", "Мужчины") с пустыми ячейками данных теперь получают gridSpan на всю ширину таблицы. ✅ **Исправлено** — добавлен метод `_apply_group_header_spans`.

### Низкие
- **[x] Стиль List Paragraph** — конвертер теперь использует разные стили для bullet и numbered списков: `Normal` для маркированных (как в ОБРАЗЕЦ) и `List Paragraph` для нумерованных. ✅ **Исправлено**
- **Точка в конце заголовков ячеек** — метод `_setup_table_header()` убирает точку из ячеек шапки. Проверка ОБРАЗЕЦ показала: в заголовках точек в конце нет, поведение конвертера корректно.
- **Подписи рисунков с полем SEQ** (выявлено при аудите «Эталон.docx» в v2.5.0) — аудит ищет подписи по тексту `^Рисунок\s+\d+`, но номер в подписи находится в поле SEQ и не попадает в текст, поэтому подписи рисунков не распознаются (предупреждение «не для всех рисунков есть подписи»). Нужен поиск подписей с учётом полей SEQ.

## 11. Перекрёстные ссылки на таблицы/рисунки и оглавление — детальный анализ (задача №27)

> Сценарий: основная функция форматировщика — конвертация Markdown → DOCX
> (`md_to_docx.py`), а НТД 01-2013 (август 2026) требует, чтобы ссылки на
> таблицы/рисунки в тексте были оформлены «Перекрестной ссылкой» Word.
> Анализ выполнен 2026-08-25 по итогам v2.5.0.

### 11.1. Целевой формат (что требует РИ)

П. 2.10.17 (таблицы) и 2.11.5 (рисунки): «На все таблицы (рисунки) должны быть ссылки в тексте, оформленные с помощью "Перекрестной ссылки"». В терминах OOXML:

- **Подпись**: «Таблица 1 …» с **закладкой** (`<w:bookmarkStart w:name="_Ref…">`) вокруг текста номера; в образце номер — поле `SEQ Таблица \* ARABIC`.
- **Ссылка в теле**: поле `REF _Ref… \* MERGEFORMAT` — отображает текст закладки («Таблица 1»), обновляется по F9, кликабельна (Ctrl+click).

**Подтверждено образцом «Эталон.docx»**: подпись `Таблица <SEQ> Сведения…` содержит `bookmarkStart _Ref236126496`; в теле — `instrText: REF _Ref236126496 \* MERGEFORMAT`. Требуемый результат — именно REF-поля, а не просто упоминание номера в тексте.

### 11.2. Текущее состояние конвейера (гэпы)

| Звено | Текущее состояние | Требование РИ |
|---|---|---|
| Подпись | «Таблица N» — литеральный текст, без закладок и SEQ (глобальный счётчик конвертера) | закладка (+SEQ) |
| Ссылка в теле | автор пишет «…в таблице 1» обычным текстом | REF-поле |
| Аудит ссылок | только для рисунков: regex «рисунок N»/«рис. N» по тексту (`audit_engine.py:776–804`); для таблиц — отсутствует; `content_validator._validate_numbering` проверяет лишь последовательность номеров | проверка полноты REF-ссылок |
| Оглавление | конвертер не вставляет поле TOC; кастомные стили (`01_Раздел` и др.) без `outlineLvl` → автосодержание Word не собирается | п. 2.6.2 — содержание настраивается в автоматическом режиме; в образце `outlineLvl` 0–3 у стилей 01/02/03/031 есть |

### 11.3. Варианты реализации

**Вариант A — полностью автоматический пост-процессинг.** После конвертации сканировать DOCX: ставить закладки на подписи, заменять упоминания «Таблица N»/«Рисунок N» в тексте на REF-поля.
- Плюсы: автор не меняет markdown.
- Минусы: ложные срабатывания на прозу («в таблице 1 приведены…»), словоформы (таблице/таблицы/табл.), диапазоны («таблиц 1–3»), повторные упоминания; regex-замена хрупкая, автор не контролирует результат. **Не рекомендуется как единственный механизм.**

**Вариант B — явные токены в markdown (рекомендуется).** Конвенция в духе pandoc-crossref:
- ссылка в тексте: `{таб:1}`, `{рис:1}`;
- конвертер при встрече токена: ① в подписи «Таблица N» ставит закладку `_RefТаблN`; ② в теле вставляет `fldSimple REF _RefТаблN \h` с кэшированным значением «Таблица N».
- Плюсы: однозначно, предсказуемо, тестируемо; номера в теле синхронизируются с подписями через F9.
- Минусы: автору нужна конвенция; перенумерация подписей остаётся ручной (REF синхронизирует только отображение).

**Вариант C — максимальная автоматизация (следующий шаг после B).** Перевести подписи на **SEQ-поля** (как в образце) — Word нумерует таблицы/рисунки сам, REF берёт номер из SEQ. Убирает ручную перенумерацию полностью, но требует, чтобы автор не проставлял номера в markdown-подписях (либо токен `{таб:auto}`).

### 11.4. Объём работ

Конвертер (`md_to_docx.py`, ~120–160 строк):
1. Закладка вокруг номера в подписи (`bookmarkStart`/`bookmarkEnd`) — ~30 строк.
2. Токены `{таб:N}`/`{рис:N}` → `fldSimple REF … \h` — ~50 строк.
3. (опц.) SEQ-нумерация подписей — ~40 строк.
4. Маркер `{toc}` → поле `TOC \o "1-3" \h` + `outlineLvl` 0–3 в стилях заголовков (01_Раздел→0, 02_Глава→1, 03_Пункт→2, 031_Подпункт→3) — ~40 строк.

Аудит (задача №27, ~80–120 строк):
1. У каждой подписи «Таблица N»/«Рисунок N» есть закладка.
2. На каждую подпись есть ≥1 REF-поле в теле (заменить текущий regex-подход для рисунков; добавить для таблиц).
3. REF на несуществующую закладку — CRITICAL.
4. Наличие/корректность TOC-поля.

Тесты: 3–5 новых тестов (закладки на подписях, REF в теле, аудит ловит отсутствие ссылки, корректность `\h`).

### 11.5. Ограничения и риски

- Нумерация остаётся за автором (вариант B): REF-поля синхронизируют отображение, но не перенумеровывают подписи — для полной автоматизации нужен вариант C (SEQ).
- Смешанные ссылки («таблиц 1–3») и «см. таблицу ниже» токенами не покрываются; при этом РИ требует ссылку на каждую таблицу/рисунок.
- fldSimple/REF-поля валидны для Word и не ломают документ (подтверждено образцом).
- Вывод: реализуемо в рамках задачи №27; рекомендуемый путь — вариант B (токены + закладки + REF) с последующим переходом к C (SEQ); аудит — по полям, а не по тексту.
